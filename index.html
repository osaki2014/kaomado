1 全体の流れ

毎フレーム（約60回/秒）、次の順に処理し、出来上がったキャンバス映像とマイク音声を相手に送ります。相手には演出込みの映像がそのまま届きます。

カメラ → 顔のランドマークと表情（MediaPipe Face Landmarker）
       → 顔を漫画の線画に変換・デフォルメ（WebGL シェーダー）
マイク → 声の大きさ・高さ・抑揚・揺れ（自前の信号処理）
       → 音声認識で文字に（Chrome の Web Speech API）
表情＋頭の動き＋明るさ＋声＋言葉 → 場面を推定（5種）
       → 構図（顔の大きさと位置）・コマの形・背景演出・漫符
声の特徴＋言葉 → 吹き出しの種類（5種）→ 形・書体・縦書きで描画
すべてを1枚のキャンバスに合成 → captureStream で送信（WebRTC / PeerJS）

2 顔の追跡と表情

MediaPipe の Face Landmarker を VIDEO モードで使い、顔の478点と、表情を表す52個のブレンドシェイプ（0〜1）を受け取ります。

  • 顔の位置と大きさ：478点の外接矩形の中心と一辺（幅・高さの大きい方）。毎フレーム 値 ← 値 + (新しい値 − 値) × 0.35（大きさは0.2）でなめらかにします。
  • 使うランドマーク：目尻・目頭（33・133、362・263）、虹彩の中心と縁（468・469、473・474）、鼻先（1）、唇の内側（13・14）、あご先（152）、頬（50・280）、額（10・67・297）、こめかみ（127・356）。いずれも0.5の係数でなめらかにしてから使います。
  • 表情の基準：各ブレンドシェイプの「下側の包絡線」を無表情の基準とします。値が基準より下なら速く（0.02）、上ならゆっくり（0.0005）追従させ、差分 = 現在値 − 基準 を表情の強さにします。
  • 頭の動き：顔の中心の移動量 ÷ 顔の大きさ を1秒あたりに換算し、指数移動平均（0.1）でならします。
  • 明るさ：顔の領域を16×16画素に縮小した平均輝度（15フレームごと）。線画化の明るさ補正と、場面推定の「暗さ」に使います。

3 顔の描き方（ペン画・線画・デフォルメ）

漫画の顔の特徴（調査）

商業漫画の登場人物の顔を計測した研究では、次のことが報告されています。

  • 女性向け漫画では瞳が顔幅の20%に達する人物がいる。実際の人は7.5〜10%付近に集中している。
  • 目の縦幅が大きく、円に近く描かれる。
  • 鼻が全く描かれない作品も多い。
  • 実際の人より丸顔に描かれる。

また、商業漫画の基本は、主線とベタ（黒）とスクリーントーン（網点）の3要素で明暗を表すことです。本アプリはこの2点をもとに、写真の顔を「線＋ベタ＋トーン」の白黒画にし、目を大きく丸く、鼻を小さく（ほぼ省略）、あごを細くデフォルメします。

処理（WebGL の4パス）

  1. デフォルメと明るさ補正：出力の画素 p ごとに、カメラ画像のどこを読むかを変えて顔を変形します（逆写像）。
    • 目：目の中心 e、半径 r（目の幅×0.9、縦は1.15倍の楕円）の中で、t = |p − e| / r、w = (1 − t²)²、読む位置 = e + (p − e) × mix(1, 1/s, w)。s は拡大率で、横と縦を別にし、縦を大きくして目を丸くします（日常：横1.35・縦1.5倍、驚き：1.55・1.75倍など。デフォルメ0.7のとき）。
    • 鼻：鼻先 n、半径 = 顔の大きさ×0.16の中で、読む位置 = n + (p − n) × (1 + k·w)（k = 0.5×デフォルメ）。中心から遠くを読むので、鼻が小さくなります。
    • あご：口より下で、読む x = 顔の中心x + (x − 顔の中心x) × (1 + 0.25×デフォルメ × smoothstep(下がり具合) × 横方向の減衰)。下に行くほど横に縮み、あごが細く尖ります。
    • 明るさ補正：L = 0.62 + (輝度 − 顔の平均輝度) × 1.4。部屋の明るさが違っても、肌がほぼ同じ明るさになります。
  2. 横方向のぼかしと縦方向のぼかし：σ = 1.0 と kσ = 1.6 の2種類のガウスぼかしを、分離可能なフィルタ（半径8画素）で同時に計算します。精度を保つため、中間結果は半精度の浮動小数点で保持します（対応環境のみ）。
  3. XDoG による線・ベタ・トーン：Winnemöller らの XDoG（拡張ガウス差分）を使います。 
    S = (1 + p)·G_σ − p·G_kσ        （k = 1.6、p = 線の強さ 既定18）
線 = 1                       （S ≥ ε のとき）
   = 1 + tanh(φ·(S − ε))     （S < ε のとき、ε = ベタの量 既定0.36、φ = 30）
    p を大きくするほど輪郭が強調され、ε を上げるほど暗い部分（髪・瞳）がベタになります。さらに、ε ≤ S < トーンの量（既定0.54）の中間調を、45度の網点で塗ります。網点の面積率は明るさに応じて50%→10%に変え、半径 = セル × √(面積率 / π)（セル3.6画素）で点を打ちます。最後に、鼻先から顔の大きさ×0.2以内の線を薄くして（半径の50%以内は完全に消す）、鼻をほぼ省略します。

ペン画モード（既定）：輪郭と特徴点の上にマジックの線を描く

画素の明暗から線を抜く方法（下の2モード）は、照明や影の具合で線が途切れたり、不要な影が線になったりします。ペン画モードは考え方を変え、どこに線を引くかを形の情報（領域とランドマーク）から決め、その上に一定の太さの線を描きます。Illustrator でパスを引いてブラシで描くのに近い作り方です。

線の規則：線は一定の太さで、陰影は描きません。描くのは輪郭と目・眉・鼻・口だけで、目は小さな点、口は短い1本線にします。線の数を減らすほど見る人の想像に委ねられる、という線画の考え方は、下記「参考にした事例・資料」のインタビュー記事を参照しました。特定の作品を再現するものではありません。

輪郭の線（領域分割から）

  1. 領域分割：MediaPipe の多クラス自撮り分割モデル（256×256）で、各画素が「背景・髪・体の肌・顔の肌・服・その他」である確信度を求めます（2フレームに1回）。ちらつきを抑えるため、確信度は 新 = 旧 + (今回 − 旧)×0.4 でならします。
  2. 等高線の抽出（マーチングスクエア）：髪・顔の肌・服・体の肌の確信度が0.5になる境目を、2×2画素ごとに16通りの場合分けで線分にし、隣り合う線分をつないで閉じた輪郭にします。画像の外側を0として囲むので、輪郭は必ず閉じます。
  3. 点の間引き（Ramer–Douglas–Peucker）：直線からのずれが0.7画素以下の点を省き、パスのアンカーポイントのように少ない点で形を表します。閉じた輪郭は、始点から最も遠い点で2つに分けてから間引きます。
  4. なめらか化（Chaikin の角切り）：各辺を1:3と3:1の位置で切り直す処理を2回繰り返し、角を丸めた曲線にします。描くときも、点の中点を通る2次ベジェ曲線でつなぎます。
  5. 必要な線だけ残す：同じ境目を二重に描かないよう、次のように選びます。
    • 髪：外形と前髪の生え際をすべて描きます。
    • 顔の肌：耳を含む輪郭を描きます。髪との境目は髪の線にまかせます（髪の確信度が0.35を超える部分は描かない）。
    • 服：肩の外形と襟を描きます。
    • 首・手：背景との境目だけを描きます。
    画面の縁に沿う部分と、マスク上で周長28画素未満の小さな輪郭は捨てます。

目・眉・鼻・口の線（ランドマークから）

  • 眉：眉の上端5点（70・63・105・66・107、反対側は336・296・334・293・300）を通る1本の線。
  • 目：虹彩の中心（468・473）に小さな黒い点（半径＝線の太さ×(1.05 + 0.35×デフォルメ)）。まばたき（eyeBlink）が0.5を超えたら、上まぶたに沿った短い弧にします。
  • 鼻：鼻先から小鼻へのかぎ型（4→1→2→小鼻98または327）。顔の向き (鼻先x − 顔の左右端の中点x) ÷ 顔の幅 が±0.06を超えたら、鼻筋（6→197→195→5→4）からつなげて描きます。
  • 口：閉じているときは、唇の内側の上下の中点を結ぶ短い1本線（両端を15%内側へ縮める）。口を開けたとき（jawOpen が0.22超）は、唇の内側の輪郭を黒く塗ります。
  • 領域分割を使えない環境では、顔の外周36点（FACE_OVAL）を結んで輪郭にします。

線の描き方

線の太さは、顔の大きさ×拡大率×0.013×「線の太さ」（1.4〜10画素）で、すべての線に同じ太さを使います。先端と角は丸め、ごく弱いにじみ（影のぼかし＝太さ×0.45）を付けて、紙に描いたマジックの質感に近づけています。設定では、線の太さ、髪を輪郭線だけにするか黒く塗るか、首と服の線を描くかを選べます。

すっきり線画・漫画の線画のノイズ除去

カメラの映像には細かいノイズと肌の質感があり、そのまま線を抜くと、顔に細かい斑点や途切れた短い線が出ます。そこで、線を抜く前と後に次の処理を入れています。

  1. 時間方向のならし：デフォルメ後の明るさを、前のフレームの結果と混ぜます（L = mix(今回, 前回, keep)、すっきり線画で keep = 0.55、漫画の線画で0.45）。フレームごとに変わるノイズが打ち消され、線のちらつきが減ります。
  2. バイラテラルフィルタ：Tomasi と Manduchi のバイラテラルフィルタを、横・縦の2回に分けて近似します。周りの画素を、距離（σs）と明るさの差（σr）の両方で重み付けして平均するので、輪郭のような大きな段差は残り、肌の細かい凹凸だけが平らになります。重み = exp(−x²/2σs² − (v − c)²/2σr²)（すっきり線画で σs = 4.0、σr = 0.07、漫画の線画で 2.5・0.10）。
  3. 孤立点の除去と縁のなめらか化：線を描いた後、黒い画素のまわり3×3に黒が規定数（すっきり線画で4、漫画の線画で3）未満しかなければ白にして、ぽつんとした点を消します。残った線は3×3の平均と混ぜて（0.45・0.25）、輪郭の段差をならします。

すっきり線画モード（余白の多いシンプルな線）

XDoG のように暗い面を黒く塗ることも網点を打つこともせず、ガウス差分（DoG）の暗い側だけを線にします。顔の大部分が白い余白として残り、輪郭・目・眉・口などの主な線だけが描かれます。

D = G_σ − G_1.6σ         （σ = 1.5。大きめにして細かい線を拾わない）
線 = smoothstep(−T, −0.45·T, D)   （T が小さいほど線が増える。T = 0.04 − 0.032×線の量、既定の線の量0.65）
塗り = smoothstep(暗さ − 0.03, 暗さ + 0.03, G_σ)  （瞳などごく暗い所だけ黒く。既定0.10）
画素 = min(線, 塗り)

smoothstep で縁をなめらかに変化させているので、線にギザギザが出にくくなっています。設定の「線の量」と「黒く塗る量」で、線の多さと黒い面の多さを調整できます。

どちらの線画でも、鼻のまわりは、白へ一気に切り替わる狭い範囲で線を消すようにしました。以前の版で出ていた、鼻のまわりの灰色のにじみは出なくなります。

線画の上に描き足すもの

  • 瞳のハイライト（キャッチライト）：拡大後の瞳の左上に大きな白い楕円、右下に小さな白丸を置きます。大きさは虹彩の半径（468と469の距離）×拡大率で決めます。
  • 鼻：鼻先に小さな影の線を1本だけ描きます（漫画でよくある省略表現）。
  • 漫符：喜びでは頬に照れの斜線、緊張・怒りでは額の端に怒りマーク（十字の血管）、驚きではこめかみに汗を描きます。

4 声の解析

  • 音量：2048サンプルのRMSから dB = 20·log10(RMS)。
  • ノイズフロアの追従：直近6秒のdBの下位10パーセンタイルを部屋の静けさとし、相対音量 = dB − ノイズフロア。
  • 有声の判定：相対音量が 6 + (1 − 感度)×8 dB を超えたフレーム。
  • 声の高さ：1024サンプルの自己相関で75〜400Hzの範囲の最大の山を探します（山がエネルギーの0.5倍未満なら無声）。st = 12·log2(F0/110) で半音に直します。
  • 抑揚＝発話中の半音値の標準偏差。揺れ＝連続する有声フレーム（50ms以内）の半音差の中央値（3半音以上の跳びは除外）。
  • 発話区間：認識結果が出始める直前3秒以内で最初に声が立ち上がった時刻の0.8秒前から。

5 話者への適応

判定は「その人の普段の話し方からどれだけ外れたか」で行います。発話ごとに平均相対音量・ピーク（上位10%）・抑揚・揺れ・平均の高さを記録し、直近40発話の平均と標準偏差を求めます。話し始めは初期値を4発話ぶんとして混ぜます。

平均 = (初期平均×4 + Σx) ÷ (4 + n)
分散 = (初期SD²×4 + Σ(x − 平均)²) ÷ (4 + n)
z = (値 − 平均) ÷ SD

初期値：平均相対音量18±5dB、ピーク26±5dB、抑揚2.2±0.9半音、揺れ0.45±0.2半音、高さ8±4半音（約175Hz）。普段の声でランダムな発話を2000件作って試すと、言葉の手がかりなしで、通常61%、叫び12%、小声14%、震え7%、つぶやき6%に分かれました。

7 縦書きの組版

  • 右の行から左へ。1行の字数は画面の高さの42%に収まる数（4〜14字）。長い発話は末尾の数行だけ表示。
  • 半角英数字は全角にして縦に立てる。「ー」「…」「〜」や括弧は90度回転。「、」「。」は右上へ0.55em、小書きの仮名は0.12em寄せる。
  • 行頭禁則：句読点・閉じ括弧・長音・小書きの仮名が行頭に来るときは前の行にぶら下げる。

8 場面推定（5種）

  • 表情（差分）：喜び＝笑顔 mouthSmile ÷ 0.35。驚き＝(0.6·目の見開き eyeWide + 0.4·眉上げ) ÷ 0.25。緊張・怒り＝(0.7·眉寄せ browDown + 0.3·鼻のしわ noseSneer) ÷ 0.25。落ち込み＝(0.6·口角下げ mouthFrown + 0.4·眉の内側だけ上がる量) ÷ 0.2。
  • 声（z、発話後6秒で減衰）：驚き＝0.5·(z(ピーク) − 1)/1.5 + 0.5·(z(高さ) − 1)/1.5。喜び＝(z(抑揚) + 0.5·z(高さ))/2。緊張＝(z(平均音量) + z(ピーク))/3。落ち込み＝(−z(平均音量) − z(抑揚) − 0.5·z(高さ))/3。
  • 言葉（8秒で減衰）：驚き＝えっ・まじ・うそ・本当・びっくり など。喜び＝嬉しい・楽しい・ありがとう・やった・最高 など。緊張＝怒・むかつ・ダメ・締め切り・本番 など。落ち込み＝悲しい・つらい・疲れ・不安・ごめん など。
驚き     = 0.8·表情 + 0.4·声 + 0.7·言葉 + 0.25·頭の動き
喜び     = 0.9·表情 + 0.3·声 + 0.8·言葉
緊張怒り = 0.9·表情 + 0.4·声 + 0.8·言葉 + 0.2·頭の動き
落ち込み = 0.9·表情 + 0.4·声 + 0.8·言葉 + 0.3·暗さ
日常     = 0.35（一定）

頭の動き＝(速さ − 0.8)/1.5、暗さ＝(0.35 − 顔の輝度)/0.2（いずれも0〜1）。今の場面より0.1以上高い得点のときだけ切り替え、最低2秒維持します（驚きは0.8秒で割り込み可、最低2.5秒表示）。

9 場面ごとの構図と演出

構図（顔の大きさと位置）

主役の顔は画面中央のやや上に置くと視線が集まり、三分割の交点に置くと安定します。また、余白の多い開いた構図は明るいテーマに、画面の上部に大きなものがある構図は不安や圧迫感につながります。これにもとづき、驚き・喜び・落ち込みでは顔を大きくし、場面に合う位置に配置します。

通話中のコマ割り

相手とつながると、自分と相手の映像を別々の窓として重ねるのではなく、1ページを斜めの溝で2つのコマに割って並べます。右のコマが相手、左のコマが自分です（日本の漫画は右から読むため、相手を先に読む位置にしています）。

  • 顔の位置の受け渡し：それぞれの端末は、自分の顔の窓の中心・半径と吹き出しの範囲を、映像の幅と高さに対する割合にして、約15回/秒で相手に送ります（PeerJS のデータ通信）。受け取った側は、この情報で相手の映像を切り抜いて配置します。
  • コマに収める計算：拡大率は k = 0.40 × コマの高さ ÷ 顔の半径 を基本にします。顔の円（半径の1.15倍、下は1.3倍）と吹き出しの範囲を合わせた長方形が、コマの内側（斜めの辺を除いた長方形）の幅・高さの94%に収まらない場合は、収まるまで縮めます。その長方形の中心をコマの中心に合わせ、拡大率と中心は0.12ずつなめらかに追従させます。コマの形と映像の縦横比が違うと隙間ができるので、隙間をなくすための拡大が1.25倍以内なら映像でコマ全体を覆います。それ以上必要なときは顔と吹き出しが切れないことを優先し、隙間はその人の場面の背景（トーン・ベタ・白）で埋めます。場面の種類も位置情報と一緒に送っています。
  • コマの形：ページの余白18px、溝14px、溝の上端と下端のずれはページ幅の4.5%です。コマの枠は黒い線で描き、通話中は各端末の映像に入っていた内側のコマ枠を省いて、枠が二重にならないようにしています。
  • 見せゴマ：話している方のコマを広くします。差 = (相手の声量 − 自分の声量) × 3（−1〜1）から、相手のコマの幅の割合を 0.5 + 0.12 × 差（0.38〜0.62）に近づけます。
  • 相手の端末から位置情報が届かない場合（古い版など）は、相手の映像の中央に顔があるものとして配置します。

10 演出の描画方法

  • 窓の形：箱の半径 = 1 / max(|cos(θ−傾き)|/ax, |sin(θ−傾き)|/ay)、r = R × lerp(1, 箱の半径, 四角さ) × (1 + もやもや度×0.15×揺らぎ)。揺らぎは3θ・5θ・8θの正弦波の和。
  • マスク：別キャンバスに窓を白で塗り（必要なら blur() で縁をぼかす）、顔に destination-in で重ねます。
  • コマ枠：白い太線（余白）→ 黒い線。
  • 網点トーン：45度の格子に 半径 = セル × √(面積率/π) の円。グラデーションは面積率を位置の関数に（喜び 0.28·y²、落ち込み 0.15 + 0.6·(1−y)^1.5）。開始時に一度だけ描きます。
  • 集中線：顔の中心から画面外まで細い三角形150本。内端は半径の1.3〜2.0倍で不揃い、幅0.004〜0.016rad、15%を間引き、6フレームごとに描き直し。
  • ベタフラッシュ：黒で塗り、顔のまわりに白い芯（放射グラデーション）、そこから外へ先細りの白い光を90本。上部を暗くするグラデーションを重ねます。
  • 放射線・シャボン玉・キラキラ・淡い光：顔の縁から48本の灰色の線をゆっくり回転。下から漂う輪。sin で明滅する四芒星。白い放射グラデーション（0.35→0）を screen 合成。
  • タレ線：背景は約9pxおきに上から垂れる不揃いな線。額は下へ消えるグラデーションの線。
  • 砂目ノイズ：半分の解像度で黒点を散らした画像3枚を毎フレーム切り替え。背景には強く、顔の上には1/4の濃さで重ねます。
  • 場面の重ね合わせ：場面ごとの重みを0.08ずつ目標へ近づけ、重い順に背景を重ねてクロスフェード。

11 操作・通話・注意点

  • 右上の設定ボタン（またはSキー）で設定パネルを出し入れできます。パネルは映像を見ながら調整できるよう、画面を覆わない形で開きます。ヘルプは ? ボタンかHキーです。
  • 設定パネルでは、場面と吹き出しの手動固定、顔の描き方（ペン画・すっきり線画・漫画の線画・モノクロ・カラー）、デフォルメ、線やベタやトーンの量、マイク感度を変えられます。調整用のつまみは、選んだ描き方に関係するものだけが表示されます。
  • 通話は PeerJS（WebRTC）で直接つながります。接続の仲介には公開サーバーを使っているので、常用する場合は自前のサーバーに置き換えてください。
  • 音声認識はChrome向けの機能で、音声はGoogleのサーバーで文字に変換されます。研究で使う場合は、参加者への説明に含めてください。
  • 線画化にはWebGLを使います。使えない環境では、自動的にモノクロ写真で描きます。
  • 場面推定は、漫画の慣習にもとづく経験的なルールです。感情の判定としての妥当性は検証していないので、研究に使う場合は手動固定で条件をそろえるか、別途確かめてください。しきい値と重みは、コード内の TUNE、PRIOR、BALLOON_RULES、SCENE_RULES、SCENES にまとめてあります。
